## v1.41（2026-10-08 公開）

v1.4 を使ったユーザーから、「フォルダを選択」でエラーになるという報告があったので、修正版を出す。

- **フォルダ選択のエラーの修正**: 前回選んだフォルダの親を、フォルダ選択のダイアログの最初の場所として渡していた。
  その場所が今は無いドライブ（抜いた SD カード・USB メモリなど）にあると、「指定されたドライブが見つかりません」
  （0x8007000f）でダイアログが開かず、フォルダを選べなくなる。USB を抜いた状態で開発者のアプリでも再現した
  （それまでの確認は、毎回 USB を挿してから操作していたので気づかなかった）。今ある親フォルダまでさかのぼり、
  ドライブごと無ければ場所を指定しないようにした
  - 報告したユーザーは「初めて使ったとき」とのことだが、配布物に前回の場所の記録は入っていない（インストール先に
    DB は無く、記録するのはフォルダを選んだときだけ）。一度フォルダを選んだ後に抜いたか、DB のバックアップを
    もらって復元したかのどちらかと思われる（未確認）
- **レベルの増減のチェックを、スキルごとの最大レベルで行う**（`level_change_error`）: それまではスキルに関係なく
  ±4 までとしていた。プラスは「最大レベル − 防具が元から持つレベル」まで、マイナスは元のレベルまで（元から持つスキルが
  未入力なら最大レベルまで）。最大レベルは `skill_props.json` の値（全 123 スキル。1 が 8 個、2 が 6 個、3 が 85 個、
  4 が 4 個、5 が 17 個、7 が 3 個）。ローカルの全バッチで、このチェックによる矛盾は 0 件。
  レベルの読み取りそのものは +8 まで数えられるが、これまでのデータでは +3 が 2 件、+4 以上は 0 件で、
  +4 以上は実際の画像で確かめたことがない
- **アプリで付いた見本の同梱**: バッチ #41 のラベル入力で付いたスキル名 2 個（早食い・力の解放）、スロット
  （初期スロット 6）2 個（+4・+0）、値 21 個を、画像で確かめて同梱した。同梱の見本は、文字 75・ゼニーの文字 32・
  スキル名 364・スロット 18＋25・値 767 個
- **読み取る範囲の表示**: 読み取るのは選んだフォルダの直下の `*.jpg` だけ（サブフォルダは見ない。「月」のフォルダを
  選んで別々の記録が混ざらないように、再帰にはしない）。取込タブの説明と、直下に画像が無いフォルダを選んだときの
  表示・エラーに、そのことを書いた

## v1.42（2026-10-09 公開）

v1.41 を使ったユーザーから、SD カードからコピーした画像がすべて「結果画面以外」になるという報告があったので、
修正版を出す。調査の経緯は `docs/ocr_render_difference.md`。

- **日本語などを含むパスで、画像と画面判定の見本を読み書きできない問題の修正**（コミット cbac0be）:
  `cv2.imread` / `cv2.imwrite` は Windows でこうしたパスを開けない。Windows のユーザー名が日本語だと
  `%LOCALAPPDATA%` の下の画面判定の見本が読めず、すべて「結果画面以外」になる。画像のフォルダのパスに
  日本語が入っていると、すべて「読込失敗」になる。`app/ocr/kuijin_ocr.py` の `imread` / `imwrite` に替えた
- 報告したユーザーの環境がこれに当たるかは未確認。この版で試してもらって切り分ける
  （直らなければ、`docs/ocr_render_difference.md` の「描かれ方の違い」を元の画像で調べる）
- それまで気づかなかった理由: 開発者の Windows のユーザー名も、検証に使った画像のフォルダ
  （`mhrise-skill-ocr\samples\`、USB の `Nintendo\Album\...`）も英数字だけだった。テストも一時フォルダ
  （英数字だけ）で行っていた。日本語を含むパスでのテストを足した（`test_images_and_templates_under_non_ascii_paths`）

## v1.43（2026-10-12 公開）

v1.42 を使ったユーザーの取込が「invalid literal for int() with base 10: '+1+'」で止まった。原因は、ラベル入力で
数字に「+」を選んだこと（1 個の選び間違いが見本として保存され、その後の取込すべてに効く）。これを機に、
アプリではラベルを聞くのをやめた。経緯は `docs/ocr_render_difference.md`、仕様は `docs/ocr.md` の
「アプリでは同梱の見本だけで読み、読めない画像は見てもらう」。

- アプリは同梱の見本だけで読み、確認が必要な画像（読めない値がある・その画像だけで分かる矛盾や仕様違反がある）は
  取り込まずに、回数・ゼニーと一緒に見てもらう。多すぎるとき（20 枚以上かつ 5% 超）は取込を中止する
  （ラベル入力は、同梱の見本が無い初期スロットのスロット欄だけ）
- 読める画像を増やした: 数値の欄の火花・光の粒の除去。
  スキル名とスロット欄の 2 段階の照合（ゆるい基準）は、実装して試したが、取り違えの余地があるので外した
- ドックに入れて撮った画像（TV モード）は、アプリでは取り込まない（案内を出して止める）
- ドックに入れて撮ったバッチ（`base_slot3/1010_dock`）と、別のユーザーのバッチ（`other_user/1010_1`）で出た見本を同梱。
  同梱の見本は、文字 97・ゼニーの文字 32・スキル名 380・スロット 36＋25・値 876 個
- 履歴タブのエラー欄: 欠番を 1 回だけ数える、前後の画像を出す、見出しに件数を出す。
  `import_batches.image_dir`（取り込んだ画像のフォルダ）を追加
- 残っているもの: 別のユーザーのバッチ（見本を足す前の状態）で読めない 31 行（スロット 26、スキル名 2、
  光と数字がつながった耐性 3）。レア演出（背景が赤い）の画像 27 枚のうち 17 枚が読めない。
  スロットの読み方を赤い背景に強くする案は、試して見送った（しきい値に敏感で、取り違えが出た）。
  読めなかった画像をもらって、見本を同梱して減らす

## 注意点

- **防具ごとの入力値**
  - 取込タブの初期値（初期スロット・元から持つスキル・1 回のゼニー・抽選テーブル）は、マッスル腕・ギルパレ脚・
    クシャ胴の 3 つだけ。自分で追加した防具は空欄から入力する（一度入力すれば防具ごとに記憶される）
  - 「元から持つスキル」が未入力だと、結果画面２の写っていないスキルはすべて「不明」になり、
    スキルの種類の上限による仕様違反も調べない
  - 抽選テーブルが「なし」だと、仕様違反を調べず、結果画面２の判定も並び順と種類の上限だけで行う
- **結果画面２で「不明」「不明（マイナススキルが一個以上）」になった行の値**
  - 写っていないプラスがありうるので、コストは本当より低いことがある。コスト順の並べ替えや
    コストでの絞り込みでは低い値として扱われる
  - 写っていないスキルが許可したスキルだった場合、その分が数えられず、スキル集合の検索で漏れることがある
    （誤って当たることはない）
  - これまでのデータでは、この 2 つに当たる行は 597 件中 1 件
- **仕様違反の判定では防御力の値を使っていない**
  - 防御力の読み間違い（例: +10 を +16 と読む）は仕様違反では見つからない。自己チェックの
    「±50 を超える増減」だけで検出する
- **別の解像度の画像**
  - 見本があるのは 1280x720（Switch 標準）だけ。それ以外の解像度の画像が 1 枚でもあると、取込は中断する
- **アプリで付けた見本のラベル**
  - `%LOCALAPPDATA%\QuriousCraftingLog\ocr_templates\` に保存され、同梱の見本（`app/ocr/templates/`）には戻らない。
    配布物に入れたいときは開発側で付け直す
  - 確定した後で間違いに気づいた場合、直す画面は無い（上記フォルダの JSON を手で直す）
