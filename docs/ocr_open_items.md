- **アプリで付いた見本を同梱する**: v1.4 のインストーラーを作った後、バッチ #41 のラベル入力で、スキル名 2 個

  （それ以降に増えた分もまとめて）
- **レベルの増減のチェックを、スキルごとの最大レベルで行う**（2026-10-06 決定。v1.4 には入れない）
  - 今は、スキルに関係なく「±4 を超えたらありえない」としている（`VALUE_LIMITS["level"]`）。最大レベルが 5・7 の
    スキルで +5 以上が出ると、正しい結果なのに「読み取りの矛盾」になる。逆に、最大レベル 3 のスキルの「+4」は
    この条件では引っかからない
  - 直し方: プラスは、そのスキルの最大レベルまで（防具が元から持つスキルは「最大レベル − 元のレベル」まで）。
    マイナスは、防具が元から持つスキルの元のレベルまで（こちらはすでにある）
  - 最大レベルは `app/ocr/templates/skill_props.json` に全 123 スキル分ある（結果画面の四角の数から記録したもの。
    最大レベル 1 が 8 個、2 が 6 個、3 が 85 個、4 が 4 個、5 が 17 個、7 が 3 個）
  - レベルの読み取りそのものは +8 まで数えられる（四角を左から 8 個見る）。これまでのデータでは +3 が 2 件、
    +4 以上は 0 件で、+4 以上は実際の画像で確かめたことがない

## 配布物に入っていた Windows のユーザー名と、ビルドの手順の変更（2026-10-06）

公開する前に個人情報を調べたところ、メールアドレスや本名はどこにも無かったが、Windows のユーザー名を含むフォルダの
パスが次の場所にあった。

- ドキュメント 3 か所（`PROGRESS.md`・`docs/ocr.md`・このファイル）: パスの書き方を直した。Git の履歴には残っている
  （履歴の書き換えはしない。ユーザー判断）
- exe の中: アプリの `.pyc` 73 個（ビルドしたフォルダと一時フォルダのパス）、`data/app.so`、`site-packages/bin/*.exe` 5 個。
  開発中の `__pycache__` も配布物に入っていた。v1.1〜v1.3 のインストーラーも同じと思われる（中身は未確認）

対策として、ビルドは `scripts/build_release.ps1` で行う。コミット済みのファイルだけを `C:\build\qcl` に書き出し、
一時フォルダを `C:\build-tmp` にしてビルドし、exe の中にユーザー名が残っていたらインストーラーを作らずに止まる。
`subst` でドライブを割り当てる方法は、`.pyc` には効いたが、`app.so` と付属の exe には元の場所が記録されて効かなかった。

## ビルドのやり直しで失敗したこと（2026-10-06）

`build/` の途中の生成物（`build/flutter`・`build/python-app`・`build/site-packages`）を掃除で消した後、`flet build windows` が
「Packaging Python app」で `NotADirectoryError: [WinError 267]` になった。`build/.hash`（ビルドの状態の記録。隠しフォルダ）が
残っていて、Flet が準備済みと判断し、消えた `build/flutter` の中で作業しようとしたため。`build/.hash` も消すと最初から
作り直される。このとき ISCC を続けて実行すると、古い `build/windows` のままインストーラーができてしまうので、
exe の更新日時を確かめてからインストーラーを作る。

## 注意点

- **防具ごとの入力値**
  - 取込タブの初期値（初期スロット・元から持つスキル・1 回のゼニー・抽選テーブル）は、マッスル腕・ギルパレ脚・
    クシャ胴の 3 つだけ。自分で追加した防具は空欄から入力する（一度入力すれば防具ごとに記憶される）
  - 「元から持つスキル」が未入力だと、結果画面２の写っていないスキルはすべて「不明」になり、
    スキルの種類の上限による仕様違反も調べない
  - 抽選テーブルが「なし」だと、仕様違反を調べず、結果画面２の判定も並び順と種類の上限だけで行う
- **結果画面２で「不明」「不明（マイナススキルが一個以上）」になった行の値**
  - 写っていないプラスがありうるので、コストは本当より低いことがある。コスト順の並べ替えや
    コストでの絞り込みでは低い値として扱われる
  - 写っていないスキルが許可したスキルだった場合、その分が数えられず、スキル集合の検索で漏れることがある
    （誤って当たることはない）
  - これまでのデータでは、この 2 つに当たる行は 597 件中 1 件
- **仕様違反の判定では防御力の値を使っていない**
  - 防御力の読み間違い（例: +10 を +16 と読む）は仕様違反では見つからない。自己チェックの
    「±50 を超える増減」だけで検出する
- **別の解像度の画像**
  - 見本があるのは 1280x720（Switch 標準）だけ。それ以外の解像度の画像が 1 枚でもあると、取込は中断する
- **アプリで付けた見本のラベル**
  - `%LOCALAPPDATA%\QuriousCraftingLog\ocr_templates\` に保存され、同梱の見本（`app/ocr/templates/`）には戻らない。
    配布物に入れたいときは開発側で付け直す
  - 確定した後で間違いに気づいた場合、直す画面は無い（上記フォルダの JSON を手で直す）
